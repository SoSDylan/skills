# ASD-STE100 checklist

Apply this checklist to customer articles. Exact interface labels, product names, URLs, and required domain terms are technical names.

## Words and terms

- **W1 — One term:** Use one term for each object or action. Do not alternate between synonyms.
- **W2 — One meaning:** Use each word with one meaning in the article.
- **W3 — Familiar words:** Prefer short, familiar words in their primary meaning.
- **W4 — Technical names:** Copy interface labels exactly. Explain an unfamiliar domain term at its first use.
- **W5 — Explicit references:** Make `it`, `this`, `that`, and `they` refer to one clear noun.
- **W6 — Short noun groups:** Keep noun groups to three words when possible. Do not rewrite an exact interface label.

## Sentences

- **S1 — Active voice:** State who or what does the action.
- **S2 — Sentence length:** Use no more than 20 words in an instruction and 25 words in descriptive text.
- **S3 — One instruction:** Put one user instruction in each sentence. One task-level step can cover obvious grouped form entry.
- **S4 — Simple construction:** Use simple present tense unless another tense is necessary for sequence or state.
- **S5 — Positive form:** State the action to take. Use a negative only for a necessary prohibition or product limitation.
- **S6 — Complete sentences:** Use complete sentences in paragraphs and steps. Headings, labels, and table cells can be fragments.
- **S7 — Clear conditions:** Put the condition before the action when the user must evaluate it first.
- **S8 — Vertical lists:** Use a list or table when one sentence would contain several items or conditions.
- **S9 — Minimal punctuation:** Prefer full stops and commas. Do not use semicolons to join instructions.

## Procedures

- **P1 — Numbered sequence:** Number every procedural instruction. Keep prerequisite bullets declarative.
- **P2 — Task level:** State the user task, not each click or each field, unless the workflow requires that detail.
- **P3 — Necessary actions:** Keep automatic loading, saving, and other system work outside numbered steps.
- **P4 — Final action:** Make the last numbered step the final action that the user must take.
- **P5 — Consequences first:** Put warnings and consequences before the procedure when they affect the user's choice.
- **P6 — Confirmation exception:** Include a confirmation only when it contains required information, needs another action, or is the sole reliable completion indicator for a long process.

## Audit

1. Check every term against W1–W6.
2. Check every sentence against S1–S9.
3. Check every procedure against P1–P6.
4. Rewrite each violation.
5. Report any violation that an exact interface label or required technical name makes unavoidable.
