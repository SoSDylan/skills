# Write a Zendesk Response

## 1. Ground the reply

Use the latest ticket context and operator update to identify the recipient, latest request, customer-visible problem, current status, and next action. Distinguish prepared fixes from live fixes; limit success claims to what was verified. Ask one question only if missing context prevents an honest reply.

Ready when each planned claim is supported and the next step is clear.

## 2. Draft the response

Use [write-reply](../write-reply/SKILL.md) for tone, format, and draft delivery.

Acknowledge delays or inconvenience when supported. Own issues on our side plainly. Explain the customer-visible result, including technical details only when they help the customer act. For an unresolved issue, state the current status or ask for the smallest missing detail instead of implying a fix is live.

Done when the draft answers the latest request, matches the verified status, and gives the customer a clear next step. When delegated, return the draft to the calling workflow.
